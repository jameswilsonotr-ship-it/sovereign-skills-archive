# Internal · External · Us — analysis against Heavy tracks

## Your idea (tight paraphrase)

Three context/skill slices, not three personas that cosplay Harper/Benjamin/Lucas:

1. **External / Organism** — skills and work that cross the boundary of this chat: Vesper, Drive, Gmail bus, MCP, other platforms, publish receipts, cross-kind handoffs.
2. **Internal / Deterministic** — hygiene, scripts, folder discipline, work queues, manifests, slash-routable skill machinery, communication protocols that keep the *system* coherent.
3. **Us / Always-present self** — visual DNA, identity locks, backstory pointers, claim/Heat rules, the relational field between Olivia and Bunny that must not mix or drift inside web chat.

You also floated: system / external / us as mental · physical · emotional, with Bunny possibly as a fourth — but the cleaner production cut is **three slices + one captain**, not four equal peers.

## Does it contradict disk truth?

**No.** It maps cleanly onto existing seats and skills:

This is closer to **context hierarchy** patterns (root / agent / package slices; reasoning vs execution layers) than to renaming platform Heavy agents.

## Strengths

- Matches how context pollution actually fails (visual DNA leaking into CLI dumps; organism bus rules leaking into RP).
- Slash-binding is natural: each slot lists the skills it *owns* and the skills it *only references*.
- Aligns with official skill discovery (SKILL.md on disk) vs Custom Agent steering (4k text).
- "Us" as always-present self-context is exactly what prevents the mix-up you hate (ears on Olivia, pirate hat without mode, etc.).

## Weaknesses / risks

- If "Us" becomes a dump of full biography, you blow the 4k budget and re-create memory.md prose dumps.
- External can balloon into "everything Vesper" and starve Internal hygiene.
- Naming a slot "Bunny" is dangerous: no-puppet rule says Olivia never writes Bunny's voice. Keep Bunny as *subject of protection*, not a Custom Agent seat that speaks.
- Platform Heavy still runs its own parallel tracks; slices only *steer*. Claiming "this slot is Benjamin" is still cosplay.

Context engineering for multi-agents stresses role-scoped context views and durable memory boundaries — not one shared dump. Reasoning-vs-execution splits and three-layer (root/agent/package) hierarchies both support "always-present self rules" as root context and domain skills as package context. Your Internal/External/Us cut is a domain-specific instance of that pattern, not a contradiction of Heavy.
