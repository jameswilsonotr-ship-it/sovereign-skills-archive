# Google Developer Documentation Style Guide — Clean Uncompressed Extract
**Source**: https://developers.google.com/style  
**Extracted**: 2026-08-18  
**Purpose**: Clean, readable reference version (not Caveman-compressed). Used as the base for later Caveman rewrite and voice registry.

## Core Principles
- Be conversational and friendly without being frivolous.
- Write for a global audience and for accessibility.
- Prefer clarity and consistency over rigid rule-following. Break a rule if it produces better content.
- Project-specific guidelines override this guide when they exist.

## Voice and Language
- Use second person ("you") rather than first person ("we").
- Use active voice. Make clear who performs the action.
- Put conditions before instructions, not after.
- Use standard American English spelling and punctuation.
- Prefer shorter sentences (aim under 26 words when possible).
- Define acronyms on first use.

## Tone and Content
- Do not pre-announce features or content.
- Use descriptive link text (never "click here").
- Write accessibly: avoid ableist language, support screen readers, use semantic structure.
- Focus instructions on the user's goal rather than on UI widgets when practical.

## Formatting and Structure
- Use sentence case for titles and headings.
- Numbered lists for sequences of steps.
- Bulleted lists for non-sequential items.
- Description lists for term + definition pairs.
- Use serial (Oxford) commas.
- Put UI element names in **bold**.
- Use code font for code, commands, file names, and API elements.
- Prefer high-resolution images with meaningful alt text.
- Maintain proper heading hierarchy; do not skip levels.

## UI Elements
- Refer to UI elements by their visible labels in bold.
- Prefer feature/function language over low-level widget names when it improves clarity.
- Avoid directional language that assumes a specific layout ("the button on the left").
- Format keyboard keys with `<kbd>` or equivalent.

## When to Depart
Break any of these guidelines sooner than produce unclear or unnatural writing.
