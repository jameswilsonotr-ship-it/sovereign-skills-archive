# Refactoring Clusters (Not Yet Instantiated)
**Parent**: system-roadmap  
**Created**: 2026-07-20  
**Purpose**: Holding area for major consolidation / refactoring efforts that have been identified but have not yet produced a new top-level skill or absorbed existing ones.

These are **pre-instantiation** clusters. They exist so we can collect research, observations, planning notes, and decision records before any irreversible condensation happens.

## Rules
- Every cluster gets its own subdirectory.
- Each cluster maintains its own `REGISTRY.md` of notes.
- Two primary note classes are required:
  - **Research notes** — external + internal landscape analysis directed at the refactor goal.
  - **Observation notes** — what we actually see in the current skill base (strengths, overlaps, pain points).
- Planning notes are written only after explicit feedback on observations.
- No cluster may create a new top-level skill without passing the Standing Policy (crucial to refactoring **or** clear ≥ 3:1 condensation math) and recording the decision in `SYSTEM_ARCHITECTURE_TARGET.md`.
