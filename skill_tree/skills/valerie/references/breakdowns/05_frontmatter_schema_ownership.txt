## Core Frontmatter Schema (Canonical - Valerie Owned)
Required on **every** file, chunk, and significant artifact:

```yaml
id: "20260713T2328Z-chunk-abc123"          # Stable unique ID (timestamp-slug or UUID). NEVER changes.
parent_id: "20260713T2300Z-file-raw456"    # For lineage (chunks → parent file/stage)
title: "Human-readable title"
type: chunk | stage_record | level2 | archive_shard | gps_segment | planning_doc | code_module | concept | research
date_created: 2026-07-13T23:28:00Z
modified: 2026-07-13T23:28:00Z
tags:                                    # YAML list only. No inline #tags.
  - ingestion/chunk
  - gps/cleveland
  - emotion/positive
  - provenance/greasy_x
status: raw | staged | level2 | archived | promoted | draft | active
provenance:
  source_file: "synthesis-pack.zip:gps_timeline/segment_042.md"
  stage: raw | greasy_x | sieve | archive | gps
  ingested_by: greasy_x_vX
summary: "One-sentence human summary"
description: "Optional longer description or key entities"
links:                                   # Wikilinks for relationships
  - "[[parent-file-raw456]]"
  - "[[related-gps-visit]]"
```

**Type-Specific Extensions (Valerie Templates Enforce):**
- **chunk**: chunk_index, token_count, essence_score, emotion_tags, gps_tags, vector_id (USearch link)
- **stage_record / level2**: sieve_pass, quarantine_status, promote_confidence, level2_fields_populated, validation_status
- **archive_shard**: archive_shard_id, archive_version, provenance_chain (list of prior ids), nightly_aggregate_date
- **gps_segment**: gps_segment_id, visit_id, semantic_segment, null_gps_rate, otr_tags
- **planning_doc / research / code_module**: related_proposals, module (for code), depends_on, owner (Valerie component)

## Enforcement Rules (Valerie Risk Officer + Archivist)
1. **Templates as Single Source of Truth**
   - Obsidian templates for new planning/research/code docs.
   - Python injection helpers for greasy_x emit and sieve processing (thin adapters).
   - All new files/chunks must be created via template or injection hook.

2. **Linter + Validation**
   - Obsidian Linter plugin: auto-move inline tags to frontmatter, enforce date formats, required fields.
   - Python validator in greasy_x/Valerie scripts: reject or flag schema violations on emit/process.
   - Telemetry: Log schema violations, merge success rate, ID collisions → Valerie status blocks.

3. **Unique ID + Mergeable Metadata System**
   - Stable `id` generation (deterministic timestamp-slug or UUID) in shared util.
   - Central lightweight manifest/index (Valerie-owned JSONL or sidecar) tracking id → path + stage.
   - On promotion (raw → Stage → Level-2 → archive → GPS): Merge previous frontmatter + new computed fields. Never overwrite immutable fields (`id`, early `parent_id`, core provenance).
   - Body/content stays clean; frontmatter is the structured "index + provenance" layer.

4. **Telemetry & Audit (Risk Officer)**
   - Mandatory new status blocks in Valerie reports:
     - Frontmatter coverage % (new items)
     - Merge success / lineage completeness
     - Schema violation count + examples
     - ID collision rate
     - Essence_score / emotion_tag distribution for routing decisions
   - Alerts on threshold breaches (e.g., high violation rate, low coverage).

5. **Integration with Augmentation Layer**
   - Frontmatter fields (`id`, `tags`, `essence_score`, `emotion_tags`, `summary`, `provenance`) injected as metadata into USearch/Zvec embeddings.
   - `links` become graph edges in Neo4j or memory engines.
   - `provenance_chain` enables full lineage queries in Zep/Letta/Obsidian.
   - Ties to PR-001 (streaming JSONL), PR-003 (vector sidecar), PR-005 (Valerie governance).
