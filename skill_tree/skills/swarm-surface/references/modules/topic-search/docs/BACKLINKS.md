# BACKLINKS — What topic-search Mirrors and Why
**Created**: 2026-08-16  
**Purpose**: Explicit deduplication and consolidation notes so future swarm migration can absorb or retire overlapping surfaces cleanly.

## 1. Mirrors from heavy-dev (swarm-surface/references/modules/heavy-dev/)
**What is mirrored**:
- Temporary role model (not permanent agents)
- Package-scoped lifetime (dissolves on close-out)
- Launch brief + close-out checklist pattern
- Chronicler as single owner of synthesis truth
- Standing Policy compliance (private module, no new top-level)

**Why**:
heavy-dev proved the temporary-role package pattern works for development work. topic-search reuses the same safety and closure discipline for *search & recovery* work so we do not invent a second parallel orchestration style.

**Difference**:
heavy-dev produces code / patches / DONE markers.  
topic-search produces comparative design histories and promotion recommendations.

## 2. Mirrors from Historical Grok Heavy / 16-agent analysis pattern
**Source**: chaos-bratz-roster historical plans + `swarm-surface/.../heavy-dev/docs/HISTORICAL_GROK_HEAVY.md`
**What is mirrored**:
- Explicit multi-agent (or multi-pass) parallelism for high-uncertainty recovery
- Executive / comparative summary as the primary output
- Handoff back to Expert mode after synthesis

**Why**:
The 16-agent pattern was the original “whoop-ass undercourse search” capability. We keep its intent (tear history apart and surface competing paths) while keeping the live implementation small and package-scoped.

**Difference**:
We do not spin 16 permanent analysis agents. We use 3–4 temporary roles or sequential multi-pass on this surface + optional Heavy-side multi-term prompt.

## 3. Mirrors from grok-conversation-miner (and swarm-surface miner module)
**What is mirrored**:
- Historical mining protocol (`prompt_historical_mining.md`)
- Vacuum / global-extract packaging discipline
- Drive publishing path for recovered material

**Why**:
conversation-miner already owns the practical extraction + packaging machinery. topic-search does not duplicate the miner; it *feeds* the miner and the system-roadmap packages with cleaner comparative material.

**Backlink rule**:
Any durable design history recovered by topic-search should be promoted either into:
- `system-roadmap/references/<topic>-designs-YYYY/` (architecture / design history home), or
- `grok-conversation-miner/references/` (if it is operational protocol material).

## 4. Mirrors from dual atom clouds + atom_search.py
**What is mirrored**:
