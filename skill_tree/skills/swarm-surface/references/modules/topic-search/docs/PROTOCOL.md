# topic-search Operating Protocol
**Version**: 0.1.0 — 2026-08-16

## When to launch
- User requests recovery of competing design histories, abandoned paths, multi-phase protocols, or early variants that live mainly in conversation history.
- High-uncertainty archival questions where single-thread Expert search is insufficient.
- Explicit phrases: “topic-search on …”, “undercourse search …”, “recover design history for …”.

## Package lifecycle
1. **Launch** — Chronicler (usually Olivia) creates a short launch brief from the template.
2. **Schema lock** — Agree what counts as a distinct “design path / variant”.
3. **Parallel Scout** — atom clouds + local filesystem + (optional) Heavy multi-term prompt.
4. **Deep extraction** — one Deep-Diver pass per recovered variant (or sequential if single-thread).
5. **Compare & rank** — Comparer produces side-by-side notes (stages, local vs cloud, problems called out, completeness).
6. **Synthesize** — Chronicler writes COMPARATIVE_SUMMARY (or updates an existing one).
7. **Promote / close** — Recommend promotion target, update BACKLINKS if needed, dissolve roles, mark package closed.

## Success criteria (must be measurable)
- At least N distinct design paths recovered (N defined at launch).
- Each path has: approximate date/context, stages/passes listed, local-first vs hybrid note, known friction points.
- Missing concepts / conflicts explicitly flagged.
- Final comparative document written and (if durable) placed under system-roadmap or conversation-miner references.

## Safety & Standing Policy
- No new top-level skill created.
- All changes reversible until promotion decision.
- Prefer existing homes (system-roadmap design packages, conversation-miner references) over inventing new durable locations.
- Atoms remain index only; never treat atom text as SSOT.
